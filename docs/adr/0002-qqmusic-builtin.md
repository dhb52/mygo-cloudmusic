# QQ 音乐内置进宿主，与宿主同步发版

QQ 音乐此前和外置插件一样从官方目录安装，现在改为和飞牛音乐一样由宿主的 Go module 引入并内置：`go.mod` 引 `github.com/waygu-music-plugin/qqmusic`，`internal/builtin/platforms.go` 注册 `qqmusic.Registration()`（飞牛在前，它是没选过平台时的默认平台）。理由是它和飞牛一样由我们自己维护，且是用户量最大的平台之一：内置后新装用户开箱可用，不受插件目录与 GH-Proxy 可达性的影响，宿主与这个平台也永远由同一版 SDK 编译出来。两者都是 AGPL-3.0，内置不妨碍许可。

## Considered Options

- **保持外置（改动前的现状）**：宿主与插件各自发版，插件修 bug 不必等宿主；代价是新用户要先联网装一次，目录或加速不可达时就装不上，而且宿主与插件的 SDK 契约一旦错位只能靠常驻的兼容分支兜底——删掉 `download-options` 之后，改动前的开发版插件立刻收到 `unknown-action`。
- **只在开发构建里内置**：本机能跑本地检出、发版不带，但需要一套仓库里并不存在的"开发专用接线"约定（既没有环境变量开关，也没有构建标签），且对外仍是"只内置飞牛"。
- **把 QQ 音乐做成可选安装的内置平台**（宿主带二进制、默认不启用）：多一套启用状态与两个来源的优先级规则，收益只是省下宿主的几十 MB，不如直接内置。

## Consequences

- 宿主发版即带 QQ 音乐，可执行文件变大；六个发布目标仍可交叉构建（Windows、Linux、macOS 的 amd64、arm64 均已验证）。
- 用户升级 QQ 音乐只能随宿主版本走；插件自己的目录发行继续保留，供旧版宿主安装，但新宿主会跳过目录里装的同一个包（`builtinPlugin` 判断），其账号、歌单与平台设置仍在同一个平台命名空间里。
- 发布顺序收紧：SDK → QQ 音乐 / 飞牛音乐标签 → 宿主标签。宿主 `go.mod` 里指向本地检出的两条 `replace`（`../sdk`、`../qqmusic`）必须在打标签前去掉，写进 `RELEASING.md`。
- 宿主自带的下载能力与内置插件永远同版，不会再出现"宿主删了动作、插件还在调"的错位。
