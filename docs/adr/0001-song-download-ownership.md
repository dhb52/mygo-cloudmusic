# 歌曲下载由宿主执行，下载目录是宿主级偏好

平台插件自己就能取流写盘，但我们让宿主持有整条下载通路：它已有「从平台取流→写盘」的实现（进度、取消、URL 过期续签、临时文件与原子改名），加上播放缓存与内容校验，写一遍即可服务所有平台；插件只提供入口、码率弹窗与设置行。下载目录因此是宿主级偏好，而不是每个插件各自一份——用户在一处配置，任何平台下载的成品都落在同一目录。

## Considered Options

- **插件各自实现下载**：不需要改 SDK 与宿主，但每个平台插件要重复进度、取消、重试、写盘与文件命名，且无法复用播放缓存和平台提供的内容摘要校验。
- **下载目录按插件隔离**：每个插件一个下载目录，用户要在每个设置窗里分别配置，且"系统级配置"的诉求落空。

## Consequences

- 新增下载能力必须经 SDK 下发：宿主在桌面设置里宣告 `DownloadAvailable`，**不**写进握手的 `Needs`——握手对未知需求直接拒绝启动插件，而偏好补丁对未知位整包失败，老宿主配新插件会连带保存不上其它设置。
- 下载的可用级别由宿主探测平台音源得出（探测结果在宿主内存缓存 5 分钟），插件只负责展示与选择；级别文案沿用各平台自己的写法。
- 下载与缓存互不影响：命中缓存时复制一份，缓存仍按容量上限淘汰、可被清空。因此同一首歌在磁盘上可能有缓存与下载两份。
- 平台插件不再需要自己实现文件命名、重名策略、歌词与封面的落盘。
